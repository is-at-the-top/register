# Security Policy

Security issues are different from normal bugs.

If you've found something that could compromise the registry, website, DNS system, GitHub automation, infrastructure, user data, or another part of is-at-the.top, please don't report it publicly.

## Reporting a vulnerability

Please report security vulnerabilities privately through GitHub's security reporting feature:

[Report a vulnerability](https://github.com/is-at-the-top/register/security/advisories/new)

If GitHub's private reporting isn't available, contact the is-at-the.top team through the official Discord server and ask a member of staff how to submit the report privately.

Please don't open a public GitHub issue for a security vulnerability.

## What to include

A useful report should include as much of the following as possible:

* A clear description of the vulnerability
* The affected part of the project
* Steps to reproduce the issue
* The potential impact
* Proof of concept, if available
* Any relevant logs, screenshots, or other evidence

You don't need to have everything figured out before reporting something. If you're unsure whether something is a security issue, it's better to report it privately and let us take a look.

## Please don't exploit vulnerabilities

Please don't:

* Access, modify, or delete other people's data
* Take control of accounts or infrastructure
* Disrupt the service
* Perform denial-of-service attacks
* Use a vulnerability to obtain information you don't need to demonstrate the issue
* Leave persistent backdoors or other changes behind

If you need to demonstrate an issue, keep testing to the minimum necessary to prove it.

## What happens after a report?

We'll review the report, investigate the issue, and work on a fix if necessary.

Depending on the situation, we may:

* Ask for additional information
* Confirm the vulnerability
* Deploy a fix
* Temporarily disable an affected feature
* Publish a security advisory once the issue has been resolved

Please give us reasonable time to investigate and fix a vulnerability before publicly disclosing it.

## Scope

This policy covers security vulnerabilities affecting the is-at-the.top project and its infrastructure, including where applicable:

* The registration repository
* GitHub Actions and automation
* The is-at-the.top website
* APIs and services
* DNS automation
* Cloudflare configuration
* Registry infrastructure
* Authentication and authorization
* User or registration data

Third-party services and infrastructure that are outside our control may have their own security reporting policies. Please report vulnerabilities in those services to their respective providers.

## Thank you

Responsible security reports help keep is-at-the.top safe for everyone.

We appreciate anyone who takes the time to report a vulnerability responsibly.
