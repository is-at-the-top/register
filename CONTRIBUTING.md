# Contributing to is-at-the.top

Thanks for wanting to contribute to is-at-the.top!

You don't need to be a developer to contribute. The registry is built around GitHub so that all changes can be reviewed openly, but we aim to keep the process as simple as possible.

## Registering a subdomain

If you are here to claim a `.is-at-the.top` subdomain, you don't need to contribute to the codebase.

Instead, please follow the registration instructions in the [README](./README.md) and the official documentation at [is-at-the.top/docs](https://is-at-the.top/docs).

Ensure your registration request contains only the specific information required by the registry.

## Improving the project

Found a bug? Have an idea? Want to improve the documentation? All contributions are welcome!

You can help by:

* Opening an issue to report bugs or suggest features
* Fixing typos or improving the documentation
* Fixing bugs in the registration system or core code
* Improving GitHub Actions and automation workflows
* Submitting other useful updates

Before making any large changes, please open an issue first. This allows us to discuss the proposal before you spend time implementing it.

## Pull requests

When opening a pull request (PR):

* Keep your changes focused and concise.
* Clearly explain what you changed and why.
* Ensure all automated checks pass.
* Avoid including unrelated changes.
* Do not modify registrations that do not belong to you.
* Never include secrets, API keys, tokens, or other sensitive information.
* Ensure your changes comply with the project's license and guidelines.

Please do not open a pull request just to test if GitHub works—we promise it does!

## AI-assisted contributions

You are welcome to use AI tools to assist with your contributions.

However, you are responsible for the content you submit.

Please thoroughly review and understand your changes before opening a PR. Automatically generated code can contain errors, redundancies, or security vulnerabilities.

If an AI-generated contribution does not work as intended, we will ask you to fix it before it can be merged. Submitting code you do not understand and expecting maintainers to fix it is not acceptable.

## Subdomain registrations

Subdomain registration PRs are reviewed separately from source code contributions.

A registration request may be rejected if:

* The requested name is reserved.
* The request violates the registration rules.
* The configuration format is invalid.
* The requested name is misleading, abusive, or intended for impersonation.
* The registration violates our Terms of Service.
* The request poses a security or operational risk.
* The registry team identifies any other legitimate reason for rejection.

Please note that availability does not guarantee approval.

## Review process

Pull requests are reviewed by the is-at-the.top team and automated systems.

You may be asked to make adjustments before your PR can be merged. If changes are requested, please update your existing pull request rather than opening a new one.

We reserve the right to immediately close pull requests that are clearly spam, malicious, abusive, or intentionally invalid.

## Keep it friendly

Please be respectful to other contributors, users, and maintainers.

Everyone makes mistakes. If you spot an error, point it out constructively and help fix it rather than escalating the situation.

## Questions

If you are unsure how something works, feel free to ask!

You can join the [is-at-the.top Discord community](https://discord.gg/) to chat with other members or staff.

Please do not ping individual staff members directly unless absolutely necessary. Someone will answer your question as soon as they are available.

Thank you for helping make is-at-the.top better!
